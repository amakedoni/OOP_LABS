# Четвёртая лабораторная простыми словами

Вариант 6 — три электронных прибора на одной частоте: резистор,
конденсатор и катушка. Полный построчный разбор находится в
[DOCX](oop-lab-04-defense.docx), порядок демонстрации — в
[сценарии защиты](oop-lab-04-defense-script.docx).

## Сначала понять задачу

При частоте 1000 Гц резистор 100 Ом имеет метрику 100 Ом,
конденсатор 1e-6 Ф — примерно 159.154943 Ом, катушка 0.01 Гн —
примерно 62.831853 Ом. Формулы: `R`, `1/(2*PI*f*C)` и `2*PI*f*L`.
Коллекция складывает именно эти числа. Схему соединений она не моделирует.

## Общий интерфейс

`Component` — абстрактный базовый класс. Он задаёт действия `metric`,
`print`, `read`, `clone`, но не знает конкретной формулы и полей прибора.
`= 0` после виртуального метода требует его реализации у конкретного
наследника. Создать самостоятельный `Component` нельзя.

```cpp
Capacitor capacitor(1e-6, true);
const Component& base = capacitor;
double value = base.metric();
```

Первая строка создаёт конденсатор. Вторая даёт ему другое имя через базовую
ссылку, без копирования. Третья вызывает формулу настоящего конденсатора.
Выбор реализации по настоящему типу во время выполнения — динамический
полиморфизм. `override` проверяет, что метод наследника совпал с виртуальным
методом базы. `const` после метода разрешает вызов у объекта только для чтения.

## Особые действия

Допуск есть только у резистора, признак электролитического типа — у
конденсатора, признак воздушного сердечника — у катушки.

```cpp
const Resistor* resistor = dynamic_cast<const Resistor*>(&base);
if (resistor) std::cout << resistor->tolerance();
```

Если `base` обозначает конденсатор, первая строка получит `nullptr`,
поэтому вторая не вызовет метод резистора. Если обозначает резистор,
получится адрес того же прибора, и метод можно вызвать. `dynamic_cast`
здесь не создаёт новый объект.

## Два уровня памяти

`Collection::data_` имеет тип `Component**`: это адрес массива указателей.
В каждой используемой ячейке лежит адрес отдельного прибора.

```text
Collection -> K1 [ адрес R1 | адрес C1 | адрес L1 ]
                    |          |          |
                  Resistor  Capacitor  Inductor
```

`add` принимает существующий прибор по `const Component&` и сохраняет его
независимую копию. Виртуальный `clone` вызывает `new Resistor(*this)` или
аналогичный конструктор нужного типа. Коллекция владеет новой копией,
исходник остаётся у вызывающего кода.

При росте выделяется новый массив указателей. В него переносятся адреса
приборов, старый массив удаляется. Сами приборы остаются на прежних местах,
поэтому ссылки на них сохраняются. Повторы допустимы, сортировки здесь нет.

Обычный `delete data_[i]` удаляет один прибор. Виртуальный деструктор базы
запускает деструктор настоящего типа. `delete[] data_` освобождает массив
адресов и отдельно приборы не удаляет. Присваивание `nullptr` только убирает
адрес из переменной и память не освобождает.

## Копирование и перемещение

`Collection b = a` создаёт новую коллекцию через копирующий конструктор,
несмотря на знак равенства. Она получает новый массив и новые приборы.
`b = a` меняет уже существующую коллекцию: сначала создаётся глубокая копия,
потом `swap` меняет поля. Местная копия получает прежние данные `b` и удаляет
их на выходе из `if`.

`Collection b = std::move(a)` создаёт `b` конструктором перемещения.
`b = std::move(a)` сначала удаляет прежние данные `b`, затем забирает массив
`a`. Источник становится пустым. `std::move` лишь позволяет выбрать эти
перегрузки; сам передачу адреса не выполняет. Проверка адресов защищает
самоприсваивание и самоперемещение.

Временная коллекция в копирующем конструкторе нужна и на ошибочном пути:
если второй `clone` выбросит исключение, она удалит первую созданную копию
и массив. Деструктор недостроенного внешнего `Collection` не вызывался бы.
Это проверяется последним тестом со счётчиком живых приборов.

## Чтение и операторы

`<<` и `>>` — свободные функции. Они вызывают виртуальные `print` и `read`,
поэтому реализованы один раз для базы и работают со всеми тремя типами.
Записи `Resistor 100 5`, `Capacitor 1e-6 1`, `Inductor 0.01 1` можно
напечатать и прочитать обратно. Метрику меню выводит отдельно.

`read` сначала читает местные числа и проверяет их, затем записывает поля.
Ошибочная запись сохраняет прежний прибор и ставит ошибку потока.
Сопротивление и индуктивность допускают ноль; ёмкость и частота должны быть
положительными. Ненулевой целый логический признак становится `true`.

`operator==` сравнивает метрики с точностью `1e-6`, поэтому разные типы
могут оказаться равны. `explicit operator double` требует явного
`static_cast<double>(item)` и возвращает его метрику без копирования.
Индекс возвращает существующий прибор по `const Component&` и проверяет
границы. Он не создаёт отдельный объект.

## Время жизни в меню

Коллекция создаётся перед `while`, поэтому сохраняется между пунктами.
Местный прибор каждой ветки уничтожается на выходе из неё, но его копия
остаётся у коллекции. `continue` при неверном индексе начинает новую
итерацию, сохраняя коллекцию. `break` выходит из `while`; затем выход из
`try` уничтожает коллекцию. При исключении её очистка выполняется до
перехода в `catch`.

## Проверки

24 теста охватывают формулы и контракт, потоки, ошибки параметров, владение,
глубокую копию, перемещение, самооперации, рост и исключение во время копии.
Команды запуска и проверок памяти приведены в README. Индекс и размер
работают за `O(1)`, сумма и глубокая копия — за `O(n)`, удаление — за
`O(n)`. Конструктор перемещения — `O(1)`, перемещающее присваивание ещё
удаляет прежние приборы получателя. Последовательное добавление с удвоением
имеет амортизированную стоимость `O(1)` на прибор.
